# 单价表

## 为什么单价不写在代码里

单价会变、有阶梯、有缓存折扣。写死在代码里意味着**改一次价，全部历史不可比** —— 而成本
报告最主要的用途恰恰是跨天对比。表在仓库里带版本号，改价是**新增一个文件**而不是改旧文件，
于是旧账按旧价重算得出的还是当初那个数。

另一条理由来自一次实测教训：**硬编码清单当基线会把实测偷换成查表**。清单没跟上代码时，
判据不会报警，而是用一句自信的错话指向错方向。所以这里的表只承担「单价是多少」，
「有哪些模型」由 jsonl 里实际出现的 `model` 值决定 —— 表里没有的模型会被报成**未定价**
并单独计数，不会当 0 元混进总额。

## 键名跟响应体，不跟请求

`models` 下的键必须是**上游响应体里那个 `model` 值**，不是我们请求时发过去的名字。埋点
(`ai_client.py` 的 `data.get("model")`) 记的就是响应体那个。

2026-09-22 实测：请求 `deepseek-v4-flash`，DeepSeek 响应体回 `deepseek-flash`。v1/v2 用的
`deepseek-chat` / `deepseek-reasoner` 与线上实际出现的 model 值**完全不相交**，于是每一行
都落进「未定价」、总花费恒为 0 元下限。这个失败模式很难看出来：报告不报错，它老老实实打了
「未定价 1 个」并标了下限，但一个从没对上过的表和一个「今天恰好没花钱」在输出里长得几乎一样。
所以加新模型时，判据是**去 jsonl 里看 `model` 字段实际是什么**，不是去配置里看我们填了什么。

## 分时计价与上界

DeepSeek 是分时价：峰值窗口 UTC 01:00-04:00 与 06:00-10:00 的工作日（排除中国法定节假日），
其余时段含周末整日为平峰，**平峰价是峰值的一半**。本表结构没有分时维度。

填**峰值价**，于是算出的是**上界**。理由是方向一致性：本层所有金额的诚实性建立在「这是下限，
真实值只会更高」上，而如果按平峰价填，峰值时段会被系统性低估一半，方向就反了 —— 一个被低估的
成本数字比一个明显偏高的危险得多。填峰值意味着数字偏高，看报告的人不会因此漏掉超支。

## 文件约定

一个文件一版，文件名 `v<N>-<生效日期>.json`。`monthly_cost.load_pricing()` 默认选
`effective_date` 不晚于查询日的最新一版；也可以用 `PSI_COST_PRICING` 指名某一版，
阴性判据就是这么换版的。

必含字段：

| 字段 | 含义 |
| --- | --- |
| `version` | 版本号字符串。**任何成本数字打印时都要带上它**，这是报告可追溯的唯一凭据 |
| `effective_date` | 生效日期 `YYYY-MM-DD`。选版按它，不按文件 mtime（mtime 区分不了投放与就地编辑） |
| `currency` | 币种，进报告抬头 |
| `unit_tokens` | 单价的计价单位，例 1000000 表示「每百万 token」 |
| `models` | 模型 id → 各类 token 单价 |
| `source` | 单价抄自哪里、抄的时间。**不是账单核对过的凭据** |

`models` 下每个模型的四类单价**必须分开列**：

| 键 | 乘的是 |
| --- | --- |
| `prompt` | `prompt_tokens` 里**未命中缓存**的那部分（= `prompt_tokens - cached_tokens`） |
| `cached` | `cached_tokens`。**单价不同，必须分开乘** |
| `completion` | `completion_tokens` |
| `reasoning` | `reasoning_tokens`，且仅当上游把它**排除在** `completion_tokens` 之外时才单独计 |

`reasoning_in_completion` 是个布尔开关，答的是「reasoning token 有没有已经被算进
completion 里」。OpenAI 兼容语义下 `completion_tokens_details.reasoning_tokens` 是
completion 的**明细项**而非附加项，所以默认 `true` —— 此时 `reasoning` 单价不参与乘法，
避免把同一批 token 收两遍钱。

## 缓存与延迟是两件事，不要互相解释

`cached` 单价更低，所以**缓存命中省钱**。但缓存**不省字节** —— 请求体照样要整个上传，
而首字延迟 ≈ 请求字节数 ÷ 230KB/s（实测）。因此「缓存命中率上去了但首字延迟没降」
是**正常**的，不是矛盾。报告里这两件事分节写，谁也别拿来解释对方。

## 这些数字没有与账单对过

本期**不做对账** —— 对账要登上游控制台，无法自动化，负责人已决定不做。所以每份成本
报告都会打一行「未与账单对过」。这行字是本层唯一的诚实性保障：没有它，一个抄错的单价
会以「实测成本」的名义传下去。
